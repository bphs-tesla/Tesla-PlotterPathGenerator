# 플로터 GUI 설계

웹캠으로 촬영한 이미지를 해칭해서 SVG와 G-code로 만들고, 시리얼로 GRBL 아두이노에 보내 그리는 PyQt6 GUI.

## 상태

- 섹션 1(화면, 상태 흐름)과 섹션 2(데이터 흐름, G-code)는 사용자가 대화에서 확인함.
- 섹션 3(시리얼 전송, 테스트)은 **사용자 확인 전**. 사용자 요청으로 확인 단계 없이 플랜 작성으로 넘어감.
- "설계 중 발견한 사항"은 대화 이후 코드를 조사하다 나온 내용으로, 역시 확인 전.

## 확정된 요구사항

| 항목 | 결정 |
|---|---|
| GUI | PyQt6 |
| 펌웨어 | GRBL (사용자가 "GRBL일 듯"이라고 함, 확실하지 않음) |
| 펜 올리기/내리기 | 모름. 기본값은 서보 `M3 S90`(내림) / `M5`(올림), 설정으로 변경 |
| 작업 영역 | 모름. 기본값 200 × 150 mm, 설정으로 변경 |
| 진행 방식 | 촬영 → 자동 처리 → 결과 미리보기 → 사용자가 "전송"을 눌러야 그리기 시작 |
| 그리는 중 조작 | 진행률, 일시정지/재개, 정지 |
| 카메라 | 드롭다운으로 선택 (번호 0~5 탐색, 이름 대신 "카메라 N" 표시) |
| 코드 구조 | 역할별 모듈로 분리 (사용자가 "방법 1" 선택) |

## 섹션 1: 화면과 상태 흐름

```
┌──────────────────────────────────────────────────────────┐
│ 카메라: [카메라 0 ▼] [새로고침]                            │
│ 포트:   [COM3 ▼]     [새로고침] [연결]      ● 연결됨        │
├────────────────────────────┬─────────────────────────────┤
│     카메라 미리보기          │     해칭 결과 미리보기        │
├────────────────────────────┴─────────────────────────────┤
│ [촬영 (Space)]  [다시 촬영]  [전송]  [일시정지] [정지]       │
│ 진행률: ███████░░░░░░░░  1234 / 5678 줄                   │
│ 상태: 그리는 중...                                         │
└──────────────────────────────────────────────────────────┘
```

상태:

1. **촬영 대기(LIVE)**: 카메라 미리보기가 실시간으로 나옴. 촬영 버튼과 스페이스바, 카메라 선택만 사용 가능.
2. **처리 중(PROCESSING)**: 미리보기를 멈추고 백그라운드 스레드에서 처리. 모든 버튼 비활성화.
3. **결과 확인(REVIEW)**: 해칭 결과를 표시하고 `output.svg`, `output.gcode`를 자동 저장. `다시 촬영`을 누르면 1로 돌아감. `전송`은 포트가 연결되어 있고 그릴 선이 있을 때만 활성화.
4. **그리는 중(SENDING) / 일시정지(PAUSED)**: 진행률 표시, 일시정지/재개, 정지 사용 가능.
5. 그리기가 끝나거나 정지하면 3으로 돌아감.

- 카메라와 포트는 마지막으로 고른 것을 기억함 (QSettings).
- 카메라 선택은 촬영 대기 상태에서만, 포트 연결/해제는 전송 중이 아닐 때만 가능.
- 오류(카메라 없음, potrace/Inkscape 실패, 시리얼 끊김, GRBL `error:`/`ALARM:`, 응답 없음)는 상태줄에 표시하고 안전한 상태로 돌아감. 그리던 중 오류가 나면 전송을 멈추고 펜을 올린 뒤 결과 확인 상태로 돌아감.

## 섹션 2: 데이터 흐름과 G-code

```
흑백 프레임 → processing.process → 선 목록(픽셀 좌표)
  → svg_export.save_svg → output.svg
  → gcode.generate → G-code 줄 목록 → output.gcode
  → grbl_sender로 전송
```

단계 사이에 넘기는 데이터는 "선 목록"(`list[list[tuple[float, float]]]`) 하나로 통일한다.

**이미지 처리**: 지금 `main.py`와 같은 순서와 파라미터를 쓴다. 블러 3×3 → 적응형 이진화(블록 19, C 5) → 모폴로지 열기 2×2 → potrace(turdsize 2, alphamax 1, opttolerance 0.2, unit 10) → Inkscape PNG 변환 → 원본과 합성(0.55 / 0.8 / 1) → 해칭(간격 1, 레벨 20/100/180, 45°).

고칠 버그:
- potrace에 넘기는 PBM 크기가 `640 480`으로 고정되어 있음 → 실제 이미지 크기를 사용.
- potrace 입력을 닫지 않아 멈출 수 있음 → `subprocess.run(input=...)`으로 주고받음.

**G-code 규칙**:
- 가로세로 비율을 유지하며 작업 영역에 맞춤. y축은 뒤집음(이미지는 아래로 증가, 플로터는 위로 증가).
- 그리는 순서: 현재 위치에서 가장 가까운 선 끝점부터 그림. 필요하면 선을 뒤집어 그림.
- 형식: `G21`, `G90`, 펜 올림 → 선마다 `G0` 이동, 펜 내림, `G1 ... F`로 그리기, 펜 올림 → 마지막에 `G0 X0 Y0`.

**config.toml 기본값**: 작업 영역 200×150 mm, 펜 `M3 S90` / `M5`, 펜 대기 0.2초, 속도 3000 mm/분, baud 115200, potrace `C:/potrace.exe`, Inkscape `C:\Program Files\Inkscape\bin\inkscape.exe`, 해칭 1 / (20, 100, 180) / 45°.

## 섹션 3: 시리얼 전송과 테스트 (확인 전)

**연결**: 포트를 열고(115200 baud) GRBL 시작 메시지(`Grbl ...`)를 최대 3초 기다린다. 메시지가 없으면 소프트 리셋(`Ctrl-X`)을 보내고 다시 3초 기다린다. 그래도 없으면 포트를 닫고 "GRBL 응답이 없습니다"라고 알린다. 펌웨어가 확실하지 않으므로, 잘못된 장치에 G-code를 보내기 전에 여기서 걸러낸다.

**전송**: 한 줄을 보내고 `ok`를 기다리는 방식(send-response)을 쓴다.
- `error:` 또는 `ALARM:` 응답 → 몇 번째 줄의 어떤 명령인지 담은 오류.
- 그 밖의 응답(`[MSG:...]` 등)은 무시.
- 30초 동안 응답이 없으면 오류. 일시정지 중에는 시간을 세지 않음.
- 마지막에 `G4 P0`을 보낸다. GRBL은 버퍼에 쌓인 동작이 모두 끝난 뒤에 이 명령에 `ok`를 보내므로, "완료"가 실제로 다 그린 시점이 된다.

**일시정지/재개**: GRBL 실시간 명령 `!`(멈춤) / `~`(재개).

**정지**: `!` → 0.5초 대기 → 소프트 리셋 `Ctrl-X`(GRBL 버퍼 비움) → 시작 메시지 대기 → 펜 올림 명령. 멈춘 상태에서 리셋하면 GRBL이 위치를 잃지 않는다. 오류로 멈출 때도 같은 순서로 펜을 올린다.

**스레드**: 이미지 처리와 전송은 QThread에서 실행한다. 일시정지/정지는 GUI 스레드에서 호출하고, 시리얼 쓰기는 잠금(lock)으로 보호한다.

**테스트**: pytest. 실제 하드웨어 없이 테스트할 수 있도록 다음을 대체한다.
- 시리얼: `ok`/`error` 응답을 흉내 내는 가짜 포트
- 카메라: 가짜 `VideoCapture`
- GUI: Qt offscreen 플랫폼

potrace/Inkscape가 필요한 통합 테스트는 둘 다 설치되어 있을 때만 실행한다.

## 설계 중 발견한 사항 (확인 전)

- **`hatched` 0.2.0은 현재 lock된 `shapely` 2.2.0과 호환되지 않는다.** `_build_hatch`가 첫 줄의 `MultiLineString(np.empty(...))`에서 `ValueError`로 실패하므로, 지금 `main.py`는 해칭 단계까지 갈 수 없다. 또 `hatched`는 `opencv-python-headless`를 함께 설치해서 `opencv-python`과 충돌한다.
  → `hatched`를 제거하고 해칭 알고리즘(MIT 라이선스, 약 80줄)을 `plotter/hatching.py`로 옮긴다. `scikit-image`의 `find_contours`와 `shapely` 2를 직접 사용한다. 원본과 달리, 기준보다 밝은 영역이 없는 레벨(완전히 어두운 이미지)도 해칭한다.
- 펜을 올린 뒤에도 `G4` 대기를 넣는다. 서보가 다 올라가기 전에 `G0`로 이동하면 선이 끌리기 때문이다.
- G-code 좌표는 작업 영역 안으로 잘라낸다(clamp).
